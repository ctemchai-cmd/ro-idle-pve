# เล่นเวอร์ชันส่วนตัวพร้อมเซฟในเครื่อง

เปิด [เว็บเกม](http://127.0.0.1:6173/auth) แล้วใช้บัญชีทดสอบใน [ไฟล์ส่วนตัว](../.local/play/login.md) บัญชีนี้ยังไม่ได้สร้างตัวละคร เลือกอาชีพและรูปลักษณ์ของตัวหลักเองได้ พร้อมเพื่อนหกสายให้เลือกสามคน

หน้า `/play` เป็นหน้าจอแบบเกมมือถือ (TASK-048): ทีมเดินตีมอนเป็นฉากหลัง (แสดงผลอย่างเดียว รางวัลฟาร์มยังสะสมตามเวลาและรับที่หีบ AFK ซ้ายล่าง) ปุ่มท้าบอสขวาล่าง และเมนู กระเป๋า/ทีม/ตัวละคร ด้านล่าง ใช้ทีม สกิล อุปกรณ์ และทรัพยากรจากเซฟจริง สู้บอส ผ่านด่าน รับรางวัล ฟาร์ม อัปเลเวล/ลงแต้ม/เรียนสกิล สวม/ย้าย/ล็อก/ย่อยของ Refine/Enchant/ใส่การ์ด ผสมrarityและอัปTier แล้วกลับมาสู้ได้ หน้า `/` ยังเป็นสนามทดลองแยกจากเซฟ

ถ้าเว็บไม่ได้เปิดอยู่ รันจากโฟลเดอร์โปรเจกต์:

```sh
npm run dev:local
```

หยุดด้วย Ctrl+C ใน terminal ที่รันบริการ ข้อมูลยังอยู่ที่ `.local/play/pg` ส่วนบัญชีและกุญแจของระบบอยู่ในไฟล์ส่วนตัวใต้ `.local/play` โฟลเดอร์นี้ไม่ติด Git และถูกบล็อกจาก Vite/เว็บที่ให้เล่น ไม่มีข้อมูลผู้เล่นใน build สาธารณะ

ชุดนี้ใช้ PostgreSQL/Auth/PostgREST/SMTP sink จริงบน loopback ไม่ต้องมี Docker หรือโปรเจกต์บนคลาวด์ ใช้ binary ที่ตรวจ checksum ใน `/private/tmp/ro-idle-auth-tools`; ถ้า cache เครื่องมือถูกล้างให้รัน `python3 scripts/prepare_auth_test_tools.py` ก่อน (ต้องมี PostgreSQL CLI และ dependencies ของโปรเจกต์ตาม docs/SUPABASE.md)

เกมที่เปิดจาก6173ใช้ source และ web build ที่เก็บแยกใน `.local/play/snapshot` เพื่อให้เซฟกับกติกาเวอร์ชันเดิมอยู่ด้วยกัน การแก้ source ในโปรเจกต์ไม่สลับแพตช์ของเซฟนี้อัตโนมัติ เว็บพัฒนาเดิม5173ยังแยกอยู่ การย้ายแพตช์/เซฟเป็นงาน TASK-040; ห้ามลบโฟลเดอร์เซฟเพื่อแก้ version mismatch

ขอบเขตขณะนี้ผ่าน TASK-028: Story/ฟาร์ม/ตัวละคร/สกิล/อุปกรณ์/Refine/Enchant/cards/rarity/tier ส่วนผลเฉพาะบางอาชีพยังเป็น TASK-029–034; Tower/daily/gacha/AFK12hครบ/บาลานซ์ทุกด่านและ hosted Supabase/Vercelยังอยู่ M4 แหล่งได้รับการ์ดจากกาชายังรอTASK-037 หน้าการ์ดจึงว่างในเซฟใหม่ ไม่มีการให้ของทดสอบแทนการเล่นจริงหรือdeployขึ้นคลาวด์จากคำสั่งนี้

เครื่องมือตรวจพบว่ายังไม่มีเซฟเกมก่อนเปลี่ยน frozen preview มาเป็นรุ่นนี้ เก็บ Authเดิม สำรองฐานข้อมูลส่วนตัวและเก็บ snapshotเก่าไว้ใต้ `.local/play` แล้ว `--refresh-empty-snapshot` ใช้ได้เฉพาะฐานที่ไม่มีgame saveและไม่มีบริการตัวนี้กำลังรัน; ถ้ามีเซฟจะปฏิเสธโดยไม่แตะsnapshot ไม่ใช่ระบบย้ายเซฟที่เริ่มเล่นแล้ว งานนั้นยังเป็นTASK-040 ไม่ควรลบเซฟเพื่อบังคับผ่านตัวตรวจ

ถ้าแก้เฉพาะหน้าจอ/ภาพ/asset pack โดยกติกาเกมไม่เปลี่ยน ให้หยุดบริการแล้วรัน `python3 scripts/play_local.py --refresh-compatible-snapshot` คำสั่งนี้ build ใหม่และยอมเปลี่ยน snapshot ทั้งที่มีเซฟ เฉพาะเมื่อ content_hash ไฟล์ migration และโค้ด `api/` `src/server/` gateway ตรงกับของเดิมทุก byte; สำรองฐานข้อมูลไว้ใน `.local/play/backups` และเก็บ snapshot เก่าใน `.local/play/archives` ก่อน ถ้าไม่ตรงจะหยุดด้วย `LOCAL_PLAY_REFRESH_INCOMPATIBLE_*` โดยไม่แตะ snapshot

**วิธีอัปเดตปกติ (D-058):** `python3 scripts/play_local.py --refresh-migrate-saves` ใช้ได้ทั้งตอนที่แก้แค่หน้าจอและตอนที่กติกาเปลี่ยน คำสั่งนี้สำรองฐานข้อมูล build โค้ดใหม่ ซ้อมย้ายเซฟทุกตัวก่อน ถ้าเซฟไหนไม่ผ่าน validator จะหยุดโดยไม่เปลี่ยนอะไร ถ้าผ่านจะเปลี่ยน snapshot แล้วเขียน revision ใหม่ที่ลงลายเซ็นแล้ว

ถ้ากติกาเกมเปลี่ยนจนเซฟเดิมใช้ไม่ได้ และผู้เล่นเลือกเริ่มใหม่แล้ว (เช่น D-057) ให้ใช้ `python3 scripts/play_local.py --reset-saves-for-new-content` คำสั่งนี้ทำ `pg_dump` และ export เซฟเป็น JSON ไว้ใน `.local/play/backups` ก่อน แล้วลบเฉพาะตารางเกม (บัญชีล็อกอินยังอยู่) และสร้าง snapshot ใหม่ ห้ามใช้โดยที่ผู้เล่นยังไม่ได้ตกลง

ตรวจแล้วทั้งเปิดเว็บจริง บัญชีตรวจแยก จ่าย/โหลดเซฟ รีสตาร์ตบริการ และย้ายไปโฟลเดอร์โปรเจกต์โดยคง Lv.2/ทอง978/เซฟrevision2 ของบัญชีตรวจเดิม จากนั้นลบบัญชีตรวจออกโดยไม่สร้างตัวละครแทนผู้ใช้ ดู [หลักฐาน](../plan/evidence/local-play-review.json)

## เล่นจากมือถือในวง Wi-Fi บ้าน (D-075)

หยุดบริการเดิม (pid ใน `.local/play/running.pid`) แล้วเปิดด้วย `python3 scripts/play_local.py --lan` (ครั้งแรกหลังอัปเดตโค้ด gateway ให้ใช้ `--refresh-migrate-saves --lan`) บรรทัดผลลัพธ์จะมี `lan_url` เช่น `http://192.168.1.101:6173/play` ให้เปิดที่อยู่นั้นบนมือถือที่ต่อ Wi-Fi เดียวกัน แล้วล็อกอินด้วยบัญชีเดิม (ดูใน `.local/play/login.md` บน Mac) ครั้งแรก macOS อาจถามว่าให้ `node` รับการเชื่อมต่อเข้าไหม ให้กด Allow

เปิดเฉพาะ gateway (หน้าเว็บ + `/auth/v1` + `/rest/v1` + `/api`) ฐานข้อมูล/บริการอื่นยังฟังแค่ 127.0.0.1 และปิดการสมัครบัญชีใหม่ระหว่างโหมดนี้ หน้าเป็น http ธรรมดา รหัสผ่านจึงวิ่งแบบไม่เข้ารหัสใน Wi-Fi บ้าน — อย่าใช้บน Wi-Fi สาธารณะ ไม่ต้องการ LAN ก็เปิดแบบปกติโดยไม่มี `--lan`
