# แผนเกม Idle RPG — ฉบับร่าง 0.8

> ร่างก่อนเริ่มคุยรายละเอียดเกม เก็บไว้เป็นประวัติและบริบท assets แผนปัจจุบันอยู่ที่ [plan/overview.md](../plan/overview.md) และ [รายละเอียดระบบ](../plan/design/01-game.md) โดยทีม 4 คนยืนยันแล้ว ตัวเลข/ขอบเขตที่เป็นข้อเสนอในร่างนี้ไม่ใช่ข้อสรุปล่าสุด

วันที่: 18 ตุลาคม 2026

เอกสารนี้ใช้คุยและปรับแผนร่วมกัน ข้อเสนอด้านเกมเพลย์และตัวเลขทั้งหมดด้านล่างยังเปลี่ยนได้

## 1. สิ่งที่ผู้เล่นยืนยันแล้ว

- ทำเป็นเกมเว็บ เล่นคนเดียวบนเครื่องตัวเอง
- ทำต้นแบบไว้เล่นเวลาว่าง ยังไม่มีแผนแชร์หรือหารายได้
- ใช้ Ragnarok Idle Adventure Plus เป็นแรงบันดาลใจ
- ใช้ภาพจาก Ragnarok PC Classic โดยเน้นหาไฟล์ที่พร้อมใช้และแอนิเมชันครบ
- ฉากหลังและ UI ขอให้เข้าธีมกับโลกเกมและตัวละคร ไม่จำเป็นต้องเหมือน RO Classic เป๊ะ เลือกหรือออกแบบใหม่ได้เมื่อภาพรวมเข้ากัน
- ผู้เล่นยืนยันให้โฟกัสการทำเกมไว้เล่นเอง ไม่แจกจ่าย; การสำรวจแอสเซ็ตต่อจากนี้เน้นความพร้อมด้านเทคนิค
- ออกแบบสกิล สูตรต่อสู้ และบาลานซ์ของเราเอง
- ภาพการต่อสู้เน้นหันขวาเทียบซ้าย ใช้การพลิกภาพได้ ไม่ต้องเก็บทุกทิศในชุดที่นำมาเล่น
- ต้องการคลังที่หลากหลาย ครอบคลุมอาวุธ สกิล เอฟเฟกต์ และทุกอาชีพที่หาได้ พร้อม metadata สำหรับใช้ซ้ำ

## 2. แนวทางที่เสนอ

เกม Idle RPG ภาพ 2D ที่ความสนุกอยู่ที่การเลือกอาชีพ จัดสกิล และปรับอุปกรณ์เพื่อผ่านบอส

วงจรหลัก: เลือกด่าน → ต่อสู้อัตโนมัติ → รับ EXP/เงิน/อุปกรณ์ → ปรับตัวละครและสกิล → ท้าทายด่านถัดไป

เริ่มจากฉากต่อสู้แบบอยู่กับที่ ใช้ฉากหลังและตัวละครเคลื่อนไหว แผนที่เดินสำรวจและโลก 3D ค่อยประเมินภายหลัง

จุดที่ต้องตัดสินใจร่วมกันก่อนลงรายละเอียดระบบ:

- เล่นตัวละครหลักคนเดียว หรือจัดปาร์ตี้หลายตัว? ร่างนี้ใช้ปาร์ตี้ 4 ตัวเป็นสมมติฐานชั่วคราว
- ต้องการค่าสเตตัสแบบ STR/AGI/VIT/INT/DEX/LUK หรือค่าสำหรับต่อสู้โดยตรง?
- อยากให้การเปลี่ยนอาชีพและจัดบิลด์ลึกแค่ไหน?

ข้อจำกัดที่ตรวจพบ:

- มี 9 STR effect ที่ยังมี texture ขาดหรือพาธกำกวม รวม 31 พาธ ทดสอบขอจากแหล่งที่สองแล้วตอบ 404 เช่นกัน ระบุเป็น `source_dependencies_missing` ใน [coverage.json](../assets/ro/library/coverage.json) หลีกเลี่ยงชุดเหล่านี้เมื่อต้องการเอฟเฟกต์สมบูรณ์
- มี ACT 52 ไฟล์ไม่มี SPR ชื่อคู่กัน เก็บรายชื่อไว้ใน inventory แต่ไม่ได้เก็บ raw ACT หลังลบต้นฉบับ
- รายการสกิลอ้างอิงภายนอกมี 1,732 ID จากหลายเวอร์ชัน รวม NPC/สกิลต่อเนื่อง จึงไม่เท่ากับจำนวนไอคอนในไคลเอนต์นี้ ดู [skill-coverage.json](../assets/ro/library/skill-coverage.json)
- เอฟเฟกต์บางชนิดสร้างด้วยโค้ดของไคลเอนต์ ไม่ได้มี animation clip สำเร็จหนึ่งไฟล์ต่อสกิล เก็บ effect table/skill mapping ไว้แล้ว แต่เกมใหม่ต้องมีตัวเรนเดอร์หรือเลือกเอฟเฟกต์ภาพที่เหมาะสม
- สถานะผ่านการแปลง/ตรวจ checksum แยกจากการตรวจด้วยสายตา ไม่ได้เปิดตรวจภาพทีละชิ้นทั้งคลัง

ใช้ [catalog.json](../assets/ro/catalog.json) เปิดดัชนีหมวด หรือค้นจาก [search.tsv](../assets/ro/library/search.tsv) แล้วอ่าน sidecar เฉพาะไฟล์ที่ใช้ ไม่วิเคราะห์รูปซ้ำทุกครั้ง ใช้ [skill-assets.json](../assets/ro/library/skill-assets.json) เชื่อมชื่อสกิลกับไอคอน เอฟเฟกต์ และเสียงโดยตรง เช่น [Storm Gust](../assets/ro/library/skill-assets/89.json) ข้อมูลภาพแยกจากสกิลและบาลานซ์ของเกมใหม่

## 5. สกิลและบาลานซ์ของเรา

ออกแบบแต่ละบทบาทให้มีปัญหาที่แก้ได้ต่างกัน เช่น รับการโจมตีแรงเป็นครั้ง ๆ, เก็บศัตรูหลายตัว, ทำดาเมจบอส หรือช่วยทีมอยู่รอด

ตัวอย่างแนวสกิลสำหรับคุยต่อ:

- แทงก์: ยั่วยุพร้อมลดความเสียหาย หรือรับความเสียหายแทนเพื่อน
- ระยะไกล: ยิงเป้าเดี่ยวต่อเนื่อง หรือวางสถานะที่ให้ผลเมื่อโจมตีซ้ำ
- เวท: ระเบิดความเสียหายหมู่ หรือสะสมความเสียหายตามเวลา
- สนับสนุน: ฮีลตามเงื่อนไข HP หรือใช้โล่ป้องกันก่อนรับการโจมตี

ยังไม่ล็อกสูตรหรือตัวเลขสกิลจนกว่าจะเลือกรูปแบบตัวละครและสเตตัส

แนวทางทำบาลานซ์:

1. แยกข้อมูลสกิล ศัตรู อุปกรณ์ และตารางความคืบหน้าออกจากโค้ดต่อสู้
2. ใช้ตัวจำลองต่อสู้ที่ไม่ต้องวาดภาพ เพื่อทดลองหลายบิลด์ได้เร็ว
3. วัดเวลาฆ่าศัตรู อัตราชนะ ดาเมจ/ฮีล และสาเหตุที่แพ้
4. ใช้ศัตรูหลายประเภทเป็นโจทย์ทดสอบ เพื่อให้การเปลี่ยนสกิลมีผลจริง
5. ปรับความแรง คูลดาวน์ เงื่อนไข และการเลือกเป้าหมาย ก่อนเพิ่มระบบใหม่

เป้าหมายทดลอง: ผู้เล่นที่แพ้บอสควรมองเห็นสาเหตุ และมีวิธีแก้ผ่านการจัดบิลด์หรืออัปเกรดที่เข้าใจได้

## 6. โครงสร้างสำหรับเว็บเล่นคนเดียว

ข้อเสนอเครื่องมือ: TypeScript สำหรับกติกาเกม, Phaser สำหรับฉากต่อสู้ 2D และ HTML/CSS สำหรับเมนู เครื่องมือยังปรับได้ก่อนเริ่มเขียนจริง โดย Phaser มีเอกสารรองรับเกม 2D บนเบราว์เซอร์และ TypeScript

แยกงานออกเป็นส่วนหลัก:

- กติกาเกม: สเตตัส คูลดาวน์ บัฟ ดีบัฟ การเลือกเป้าหมาย และรางวัล
- ข้อมูลเกม: อาชีพ สกิล ศัตรู ด่าน อุปกรณ์ และค่าใช้จ่าย
- ภาพและเมนู: แสดงเหตุการณ์จากการต่อสู้ จัดทีม และหน้าตัวละคร
- เซฟ: ใช้ IndexedDB พร้อมเลขรุ่นข้อมูล เพื่อปรับรูปแบบเซฟในอนาคต

รันบนเครื่องผ่าน local server ใช้ไฟล์แอสเซ็ตภายในโปรเจกต์ได้ทั้งหมด

รางวัลตอนปิดเกมใช้เวลาที่ผ่านไปและอัตราฟาร์มของด่านที่ผ่านแล้ว ไม่ให้ผ่านบอสหรือปลดล็อกด่านใหม่อัตโนมัติ ถ้านาฬิกาย้อนหลังให้เวลาที่ใช้คำนวณเป็นศูนย์ และจำกัดเวลาสูงสุดตามเพดานที่ตั้งไว้

เบราว์เซอร์อาจลดความถี่การทำงานเมื่อซ่อนแท็บ จึงต้องคำนวณเวลาจากเวลาที่ผ่านไป แทนการนับจำนวนครั้งที่หน้าจออัปเดต

ข้อจำกัดที่ต้องรองรับ: การล้างข้อมูลเว็บไซต์อาจลบเซฟ และการเปลี่ยนเครื่อง/เบราว์เซอร์ต้องใช้ไฟล์ส่งออกเซฟ

## 7. ลำดับทำงานและเกณฑ์ผ่าน

| ช่วง | งาน | ถือว่าผ่านเมื่อ |
| --- | --- | --- |
| 1. ตกลงรูปแบบ | เลือกตัวละครเดี่ยว/ปาร์ตี้ สเตตัส และสำรวจแอสเซ็ต | ระบุระบบหลักและภาพที่ใช้เริ่มงานได้ |
| 1ก. พิสูจน์ภาพ (มี lab แล้ว) | ใช้ตัวอย่าง ACT/STR และภาพตรวจที่เก็บไว้เป็นฐาน | ผ่าน smoke test 304 samples; ตรวจฉาก/อุปกรณ์ที่เลือกใช้จริงซ้ำเมื่อเปลี่ยนรูปลักษณ์ |
| 2. ต่อสู้ให้ได้ก่อน | ตัวละคร 1 ตัว ศัตรู 1 ตัว โจมตี สกิล และจบการต่อสู้ | ค่าพลังกับคูลดาวน์เปลี่ยนผลการต่อสู้ได้ถูกต้อง |
| 3. วงจรการเล่น | เพิ่มด่าน EXP เงิน อุปกรณ์ และเซฟ | เล่นต่อเนื่อง 10–15 นาที แล้วปิดเปิดกลับมาเล่นต่อได้ |
| 4. สร้างบิลด์ | เพิ่มบทบาทและสกิลตามรูปแบบที่เลือก พร้อมบอส | เปลี่ยนบิลด์แล้วเห็นผลต่อโจทย์ศัตรูต่างชนิด |
| 5. Idle และภาพ | รางวัลตอนปิดเกม แอนิเมชัน เสียง และปรับบาลานซ์ | กลับมาแล้วได้รางวัลถูกต้อง เมนูและการต่อสู้อ่านเข้าใจ |

ไม่กำหนดวันเสร็จจนกว่าจะตกลงขอบเขตและเห็นความพร้อมของแอสเซ็ต
