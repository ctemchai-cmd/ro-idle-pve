# ผลลดพื้นที่คลังแอสเซ็ต

วันที่: 18 ตุลาคม 2026 (Asia/Bangkok)

ตรวจพื้นที่จริงของ `assets/` ก่อนปรับรอบนี้: ข้อมูลไฟล์ 1.25 GB / พื้นที่บนดิสก์ 1.54 GB แพ็กต้นฉบับ ZIP/GRF/System ประมาณ 8 GB ถูกลบไปในรอบก่อนแล้ว ตัวเลข 10 GB ที่เห็นอาจเป็นค่าก่อนการลบ; ผลตรวจรอบนี้ไม่ได้พบ source payload เหลืออยู่

| การวัด | ก่อน | หลัง |
| --- | ---: | ---: |
| ขนาดข้อมูลไฟล์ | 1,252.3 MB | 919.0 MB |
| พื้นที่บนดิสก์ (allocated blocks) | 1,540.9 MB | 1,194.0 MB |
| จำนวนไฟล์ทั้งหมด | 122,886 | 107,897 |

ลดพื้นที่บนดิสก์ประมาณ **346.9 MB (22.5%)** ขนาดข้อมูลไฟล์ต่างจากพื้นที่บนดิสก์เพราะไฟล์เล็กจำนวนมากมีพื้นที่จัดสรรขั้นต่ำ ตัวเลขหลังวัดก่อนเพิ่มรายงานฉบับนี้และปรับ timestamp ผลตรวจ จึงอาจต่างเล็กน้อยเมื่อวัดซ้ำ

## สิ่งที่ปรับ

- ย่อ JSON ที่สร้างอัตโนมัติ โดยรักษาทุก field, ค่าเฟรม, timing, source references และ annotations ไว้ครบ แต่ไม่จัด indent ยาวทั้งคลัง
- รวมไฟล์สื่อที่เหมือนกันทั้ง SHA-256, ขนาด และทุกไบต์ จำนวน **14,994 ไฟล์** แล้วลบสำเนาหลังสร้างดัชนีใหม่และตรวจผ่าน
- Native library ยังคง **60,460 asset ID** แต่ใช้ไฟล์สื่อจริง **45,466 ไฟล์** ร่วมกันได้ พร้อมชุดเริ่มต้นอีก 44 รายการ รวม 60,504 asset ID
- ไม่รวมข้อมูล ACT/STR ของคนละแอสเซ็ตเข้าด้วยกัน แต่ละรายการยังมี sidecar เฉพาะของตัวเอง พาธภาพ/เสียงที่แชร์อยู่ใน `file.path` และประวัติพาธเดิมใน `shared_media`
- ไม่บีบอัดภาพซ้ำ ไม่ย่อภาพ ไม่ลดสี และไม่เปลี่ยนเสียง ทุกไฟล์สื่อที่เหลือเหมือนกับก่อนปรับทุกไบต์
- เปลี่ยนตัวเขียน JSON ของ importer/indexer ให้เก็บแบบ compact ต่อไป Small starter metadata เช่น `bash.meta.json` ยังจัดบรรทัดให้อ่านง่าย

`catalog.total_bytes` นับขนาดตามการอ้างอิงของแต่ละ asset ID จึงอาจนับสื่อที่แชร์ซ้ำกัน ค่า `catalog.storage.unique_media_bytes` คือขนาดไฟล์สื่อ native ที่ไม่ซ้ำจริง ปัจจุบัน 601.9 MB ส่วนขนาดทั้งโฟลเดอร์รวม metadata, indexes, ตารางอ้างอิง และรายงานด้วย

## ตรวจความครบ

- ตรวจ checksum / JSON / atlas bounds / ACT frame references ของ native library 60,460 รายการ และชุดเริ่มต้น 44 รายการ: ผ่าน
- ตรวจเส้นทางสกิลไปยังภาพ/เสียง/metadata ที่เหลือจริง รวม Storm Gust: ผ่าน
- อาชีพอ้างอิง 85/85 แบบยังมีข้อมูลครบ ไม่มีการตัดอาชีพหรือสกิลออกเพื่อลดพื้นที่
- ทดสอบ importer / optimizer / การป้องกันลบไฟล์ที่ยังมีการอ้างอิง รวม 18 กรณี: ผ่าน
- ข้อจำกัดจาก source texture ของ 9 เอฟเฟกต์ยังระบุไว้ใน coverage เช่นเดิม

## ใช้งานต่อ

ตาม `meta_path` จากดัชนี และ `file.path` จาก sidecar เสมอ ห้ามเดา metadata จากชื่อไฟล์ภาพที่แชร์กัน เช่น [Storm Gust](library/skill-assets/89.json) ยังคง metadata ของ `stormgust.str` แม้ bitmap จะใช้ร่วมกับรายการอื่นที่เนื้อหาเหมือนกัน

ข้อมูลเครื่องอ่าน: [storage-optimization.json](storage-optimization.json) / [storage-cleanup-plan.json](storage-cleanup-plan.json) ผลตรวจ: [validation.json](library/validation.json)

นำกลับมารันได้ด้วย `python3 scripts/compact_ro_storage.py` โดยไม่ถอดรหัสภาพหรือดาวน์โหลดต้นฉบับใหม่
