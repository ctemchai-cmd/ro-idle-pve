# TASK-043 — ตั้ง build/deploy และ Vercel Preview ที่แยกเซฟทดสอบ

Milestone: M4 · ประเภท: พัฒนา/ตรวจรับรุ่นแรก · รุ่น: Class 2 / Lv.70

อ้างอิง: [เซฟและ deploy](../design/07-cloud-save-and-deployment.md), [ข้อสรุป](../decisions.md), [workflow](../workflow.md)

## งานที่ต้องรอก่อนหน้า

- TASK-019 — ทำ runtime asset pack จาก metadata และ dependency จริง
- TASK-021 — ตั้ง Supabase Auth ฐานข้อมูลเซฟและสิทธิ์เจ้าของ
- TASK-025 — ทำ Story ฟาร์มและวงจรเล่นที่เซฟได้

ใช้ผลส่งมอบที่ผ่าน review ของงานข้างต้นตามรายละเอียดงานนี้ อ้างด้วย ID และค้นไฟล์จากโฟลเดอร์สถานะปัจจุบัน

## เป้าหมายและผลส่งมอบ

- Vercel build/preview configuration และขั้นตอน deploy ซ้ำ
- preview URL ที่เล่นวงจรหลัก/Auth/cloud save ได้บนข้อมูลทดสอบ

## ขอบเขต

- รวม: ผลลัพธ์ที่ระบุในชื่อและรายละเอียดงานนี้ตามข้อมูลรุ่นแรกที่ review แล้ว
- อยู่นอกงาน: การพัฒนาระบบ Hi-class/Awaken/Artifact, Class 3/Pet/Rune, dashboard หรือ AI ค้นบิลด์อัตโนมัติ; ส่วนอนาคตบันทึกจุดต่อไว้ตาม design

## รายละเอียด

สร้างเส้นทาง deploy ของจริงตาม stack ที่เลือก คัดเฉพาะ runtimepack ตรวจ env/authredirect/SPA routes/headers/cache และแยกข้อมูล preview จาก production ยังไม่ย้ายเซฟผู้เล่นไปใช้ production ในงานนี้

## ขั้นตอนทำงาน

1. กำหนด build/output/env และ assetpackentry ที่ทำซ้ำได้
2. deploypreview และเชื่อม Supabase ทดสอบพร้อม redirect ที่ถูกต้อง
3. เปิด deep link/reload/login/save และตรวจ request/output/secrets

## เกณฑ์ตรวจรับ

- [ ] AC-01: build และ deploy จากขั้นตอนที่บันทึกได้โดยไม่มีไฟล์ต้นทางชั่วคราวหรือ secret ใน bundle
- [ ] AC-02: preview เปิดจาก URL จริงแล้ว login/ต่อสู้/รับรางวัล/save-load ได้ และ refresh/deep link ไม่ 404
- [ ] AC-03: preview/test/reset ไม่แก้ production save และ authredirect กลับ environment ถูกต้อง
- [ ] AC-04: ไฟล์ runtime ครบ ไม่มีการโหลดจากเว็บไซต์ asset ต้นทาง พร้อมบันทึกขนาดและ deploymentversion
