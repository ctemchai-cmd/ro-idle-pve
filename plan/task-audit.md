# ผลตรวจความชัดเจนและความครอบคลุมของ task

สถานะการทำงานล่าสุดดู [overview](overview.md) และตำแหน่งไฟล์ task ผลตรวจ/ข้อเสนอด้านล่างเก็บเป็นประวัติการออกแบบ M0 ไม่ใช่สถานะ runtime ปัจจุบัน


อัปเดต: 19 ตุลาคม 2026 · ขอบเขต: ตรวจแผน TASK-001–047; ยังไม่มีงานพัฒนาหรือเกณฑ์ runtime ที่ผ่านแล้ว

## ข้อสรุป

ครบ 47 งาน ทุกงานมี dependency ขอบเขต ผลส่งมอบ ขั้นตอน เกณฑ์ AC และช่องหลักฐาน รวม 201 เกณฑ์ จำนวนต่อ task ต่างกันตามความเสี่ยง แผนนี้ครอบคลุมการส่งมอบรุ่น Class 2 / Lv.70 ตั้งแต่ออกแบบจน deploy และมี headless simulation สำหรับใช้ตรวจบาลานซ์

M0 จำนวน 15 งานยังต้องทำจริงเพื่อกำหนดสูตร จำนวนสกิล ตารางค่าทุกระดับ จำนวนบท ดรอป/ราคา เป้าหมายบาลานซ์ UX และเทคนิคให้ครบ TASK-014 ต้องตรวจข้อมูลและเคสรับงานก่อนเริ่ม coding ทุกงานหลังจากนั้น จึงไม่ถือว่ารายละเอียดทุกค่าเสร็จแล้วเพียงเพราะสร้างไฟล์ task

การตรวจนี้ยืนยันโครงรายการงานและความครอบคลุมเท่านั้น ผลตรวจสถาปัตยกรรมแยกอยู่ใน [architecture audit](architecture-audit.md) พบ A-01–A-08 ที่ยังต้องออกแบบจริงและพิสูจน์ในงานพัฒนา การเพิ่มเกณฑ์รับงานไม่เท่ากับปิดช่องว่างหรือรับประกันว่าไม่มี technical debt

| เกณฑ์ pace/บาลานซ์ต้องมีเป้าหมายอ้างอิงก่อนวัด | TASK-010 กำหนด resource checkpoints/ช่วงเวลาสะสม; TASK-011 กำหนด scenario/budget/ช่วงผลไฟต์; TASK-041 เทียบผลจริงกับเป้าหมายเหล่านั้น |
| ต้องมีเส้นทางจาก AC ไปยังเคสที่ตรวจได้ | TASK-014 ส่ง `plan/acceptance-matrix.md` ที่ผูกทุก AC กับ case ID/input/expected result/วิธีวัด ครอบคลุมทุกเงื่อนไขย่อย |
| รายละเอียดที่อาจตกหล่นจากขอบเขตใหญ่ | ระบุการฟื้น HP/SP, ช่องสกิลว่าง, เหตุการณ์เวลาเดียวกัน, รายได้ฟาร์มระหว่างท้าบอส/โหมดอื่น และอย่างน้อยสองบิลด์ต่อสาขา Class 2 ให้ชัดใน M0 |

การปรับตอน audit แก้ข้อความ/เงื่อนไขและ dependency ต่อมาผู้ใช้ให้เตรียมรายละเอียดเพื่อเริ่มและ TASK-001/002/047 ผ่าน review แบบแล้ว การผ่านงานออกแบบไม่ใช่การผ่านเกณฑ์ runtime และไม่ได้เพิ่มแพตช์อนาคตเข้ารุ่นแรก

## ส่วนอนาคตที่ยังไม่ได้แตก task implementation

| ส่วน | มีแผนไว้ระดับใด |
| --- | --- |
| Hi-class Lv.70 / Awaken / สกิลใหม่ 3–4 ท่า / Artifact | roadmap M5 และกติกาหลัก ต้องออกแบบชุดสกิล/ต้นทุน/เนื้อหาและ migration ก่อนแตกงานแพตช์นี้ |
| Class 3 Lv.120 | มีทางอาชีพและระดับเปลี่ยน ต้องออกแบบรายละเอียดในแพตช์ถัดไป |
| Pet / Rune | บันทึกแนวทางและบทบาทแล้ว ยังไม่มีข้อมูล/เกณฑ์ครบระดับ task พัฒนา |
| Simulation การเล่นหลายวัน/ค้นบิลด์/dashboard | เตรียม shared rules/pure progression calculations/virtual time; ยังไม่ทำระบบ autoplay หรือหน้าวิเคราะห์เต็มรูปแบบในรุ่นแรก |

จึงวางทางต่อได้ถึงภาพเกมระยะยาว แต่ชุด 47 งานมีขอบเขตตรวจรับเป็นรุ่นแรก ส่วนอนาคตไม่ถูกนับว่าออกแบบและแตกงานเสร็จแล้ว

## การตรวจเชิงโครงสร้าง

ตรวจไฟล์จริงเรื่อง ID ซ้ำ/หาย หัวข้อ ขั้นตอน AC ช่องหลักฐาน dependency วน การผ่าน TASK-014 ก่อน coding และลิงก์/จำนวนงานใน overview ส่วนการตรวจเชิงเนื้อหาอ่านขั้นตอนและ AC ครบทุกงาน รวมถึงผู้ส่งมอบของ dependency และความครอบคลุมตามตารางด้านบน
