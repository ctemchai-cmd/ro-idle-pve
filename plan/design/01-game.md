# รูปแบบเกมและทีม

สถานะ: บรีฟและฐาน P-01–P-09 มีข้อสรุปแล้ว รายละเอียดที่ระบุว่า “เสนอ” ยังเป็นแนวทางออกแบบ

## ยืนยันแล้ว

- เกมเว็บเล่นคนเดียวไว้เล่นเอง ใช้ Ragnarok Idle Adventure Plus เป็น reference และออกแบบสกิล/บาลานซ์เอง
- ใช้ Supabase เก็บเซฟหลัก ล็อกอินอีเมล/รหัสผ่าน และ deploy เว็บบน Vercel; ออนไลน์เป็นหลักพร้อมเซฟสำรองในเครื่อง พักความก้าวหน้าเมื่อขาดเน็ต
- ต่อสู้แบบเวลา แต่ละตัวมีคิวสกิลของตน ทำงานพร้อมกันได้ รวมมอนสเตอร์และบอส
- จัดทีม 4 คน: ตัวหลักของผู้เล่น 1 คน + NPC 3 คน
- หน้าเลือกเพื่อนแสดงตัวละคร 6 ตัวแทน Class 1 ให้เลือกคนละตัวลง 3 slot จึงไม่มีการเลือกเพื่อนสายเดียวกันซ้ำ
- ข้อห้ามซ้ำของ NPC ยึดสาย Class 1 แม้เปลี่ยน Class 2 แล้ว เช่น NPC Knight + Crusader อยู่ร่วมทีมไม่ได้ เพราะมาจากเพื่อน Swordsman ตัวเดียวกัน
- ตัวหลักอยู่นอกข้อห้ามซ้ำนี้ เช่น ตัวหลัก Knight + NPC Knight/Priest/Wizard ทำได้
- มี Class 1: Swordsman, Acolyte, Archer, Mage, Thief, Merchant
- เลือก Active ลงคิวตัวละ 4 ช่อง Passive ที่เรียนมีผลอัตโนมัติและไม่ใช้ช่อง Active
- ทั้งตัวหลักและเพื่อนใช้แต้มลง STR/AGI/VIT/INT/DEX/LUK เอง ไม่มีการเพิ่มค่าสเตตัสตามอาชีพอัตโนมัติ เพื่อไม่ให้การโตตามอาชีพเปลี่ยนจังหวะคิวที่จัดไว้
- ตัวหลักและ NPC มีการอัปเลเวล มี Breakthrough ทุก 20 เลเวล
- ฟาร์ม AFK เพื่อหาทรัพยากรอัปตัวละครและสกิล แล้วกดปุ่มสู้บอส
- มี Story, Infinity Tower และดันเจี้ยนรายวัน
- ใช้ภาพตัวละครหันขวา/พลิกซ้าย ฉากและ UI ขอให้เข้าธีม ไม่ต้องจำลอง RO Classic เป๊ะ

## ขอบเขตและจังหวะที่ยืนยันแล้ว

- รุ่นแรกเล่นถึง Class 2; Hi-class/Awaken/Artifact เป็น milestone ถัดไป ส่วน Class 3/Pet/Rune เป็นอนาคต
- ต้องการความคืบหน้าปานกลาง มีเหตุผลให้กลับมาปรับทีมประมาณทุกครึ่งชั่วโมง และมีเป้าหมายบางอย่างที่สะสมข้ามวัน ไม่ใช่กำแพงรอ 30 นาทีทุกด่าน
- ความก้าวหน้าเพื่อนผูกกับ NPC แต่ละตัว: เลเวล สกิล Refine/Enchant/การ์ดประจำ slot เก็บไว้แม้ถอดทีม เลือกตัวใหม่เข้าช่องเดิมแล้วใช้ค่าของตัวใหม่ ไม่รับค่าจากคนที่ถอด
- ตำแหน่งหน้า 2/หลัง 2 จัดได้เอง การโจมตีปกติเลือกแนวหน้าก่อน; Provoke บังคับเป้าท่าที่อนุญาต และฮีลเลือก HP% ต่ำสุดโดยยังใช้ตามคิวแม้ทุกคน HP เต็ม
- รีเซ็ต Status/Skill และสลับอาชีพนอกไฟต์ฟรี; NPC คงสาย Class 1 และเปลี่ยนสาขาได้ ตัวหลักเปลี่ยน Class 1 ได้ รักษาเลเวลและคืนทรัพยากรบิลด์ตาม P-04
- Class 2 ที่ Lv.20, Hi-class ที่ Lv.70 และ Class 3 ที่ Lv.120; cap รุ่นแรก Lv.70 รอเปิด Hi-class การเปลี่ยนคลาสไม่เพิ่มรอบ Breakthrough ที่ 70
- Story 10 ด่านต่อบท ไฟต์ท้าจำกัด 90 วินาที แพ้เมื่อทีมหมดหรือหมดเวลา ตัวหลักตายเพียงคนเดียวไม่จบไฟต์ ท้าซ้ำฟรีและฟื้น HP/SP ก่อนเริ่มใหม่

## วงจรเกมจากบรีฟ

จัดทีม/จัดคิวสกิล → ฟาร์มทรัพยากร → อัปตัวละคร/สกิล/อุปกรณ์ → กดท้าบอส → ปลดความคืบหน้าใหม่ → กลับมาปรับบิลด์และฟาร์ม

การวางคิวควรมีผลต่อผลการต่อสู้ เช่น วาง debuff ก่อนดาเมจชุดใหญ่ หรือให้ท่าขัดร่ายมาถึงช่วงบอสกำลังร่าย สเปกปัจจุบันปล่อยตามคิวเสมอเมื่อใช้ได้ ไม่เพิ่มระบบถือสกิลหรือ AI เก็บท่าไว้รอเงื่อนไขจากการคาดเดา

## ข้อเสนอประสบการณ์ผู้เล่น

- เห็น HP/SP, ท่าที่กำลังร่าย, ช่วงพัก และช่องสกิลถัดไปของแต่ละคน
- เห็นชื่อ/แถบร่ายของบอสและสัญลักษณ์ว่าขัดได้หรือไม่
- มีข้อมูลหลังจบไฟต์: ดาเมจ ฮีล ความเสียหายที่รับ การป้องกัน และเหตุผลที่แพ้ เพื่อให้แก้บิลด์ได้
- ทดลองทีมและคิวได้โดยใช้การรีเซ็ตนอกไฟต์ฟรีตาม P-04; ต้องแสดงผลการคืนทรัพยากรให้ชัด
- ตัวเลขและระบบรางวัลควรทำให้ผู้เล่นมีทางเลือกหลังแพ้ เช่น เปลี่ยนคิว เปลี่ยนบทบาท เปลี่ยนการ์ด หรือฟาร์มพัฒนา

## เรื่องที่ยังต้องออกแบบ

- TASK-001 มี baseline resources/ต้นทุนเลเวล/แต้ม/คืนทุน/ปลดระบบใน [release scope](09-release-scope.md); อัตรารายได้และเวลาได้แต่ละเป้าหมายยังต้องออกแบบใน TASK-010
- ลง save/command contracts ตามนโยบายคืนทุนที่เลือกแล้วและพิสูจน์ว่าไม่สร้างของซ้ำใน TASK-013/022
- เป้าหมายรายสกิลและข้อยกเว้น Provoke, ระยะประชิด/ไกล, จำนวนศัตรูและการชุบชีวิต
- จุดเริ่มต้น/ด่านปลดระบบใช้ baseline TASK-001 แล้ว TASK-011 ต้องออกแบบ encounter ให้ไม่เกิด resource/unlock deadlock
- วิธีล็อกอิน การเล่นขาดเน็ต และ cap รุ่นแรกมีข้อสรุปแล้ว จำนวนบท/ข้อมูลจริงเป็นงานออกแบบต้นทางก่อนพัฒนา
