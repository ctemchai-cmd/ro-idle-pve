# เวลา การต่อสู้ และสกิล

สถานะ: ข้อกำหนดผู้ใช้ + baseline TASK-002; ใช้รายละเอียดปัจจุบันใน [combat baseline](15-combat-baseline.md) และ [combat-rules.json](../data/combat-rules.json) แทนหัวข้อร่างที่เคยเปิดไว้ด้านล่าง สูตรเป็นแบบของเกมเรา ยังไม่ใช่ผลวัด runtime balance

ข้อกำหนด D-029: ใช้ engine เดียวกับเกมสำหรับ simulation แบบไม่มีภาพและไม่รอเวลาจริง แยก clock/RNG ที่ควบคุมได้ เก็บ metrics ระดับทีม/actor/skill และ replay input/seed ได้ ดู [simulation และบาลานซ์](08-simulation-and-balance.md) สูตร/ลำดับเหตุการณ์ต้องออกแบบให้ตรวจได้ทั้ง runtime และ runner ไม่ทำกติกาคนละชุด

รอบคุยล่าสุด: [โมดูลสกิล/สถานะ/ไอเทม](12-effects-and-composition.md) และ [สมการดาเมจ/คริ/เกราะ](13-damage-crit-and-defense.md) เป็นข้อเสนอให้ตรวจต่อ ยึด Ragnarok Idle Adventure Plus เป็น reference หลักและ RO ภาคอื่นเป็นแรงบันดาลใจ ไม่อ้างสมการที่ยังไม่ได้ยืนยันว่าเป็นสูตรต้นฉบับ

## ข้อกำหนดจากผู้ใช้

- ตัวละครในทีมแต่ละตัวเลือก Active 4 ช่อง วน 1 → 2 → 3 → 4 → 1 ส่วน Passive ที่เรียนมีผลอัตโนมัติ ไม่ใช้ช่องในคิว
- Q-020: สกิลเดียวกันใส่ได้หนึ่งช่อง ตรวจด้วย logical skill ID รวม variant ของท่าเดิม ไม่เพิ่มจำนวนช่องเมื่อชื่อ/ภาพต่างกัน
- ก่อนเข้าสกิลแต่ละช่องมีช่วงรอ ขึ้นกับ Attack Speed; ตัวอย่างช่วงรอ 1.5 วินาที
- สกิลมีเวลาร่ายและเวลาพักหลังร่าย บางสกิลไม่ต้องร่าย ความเร็วร่ายมีผลกับเวลาสกิล สูตรของแต่ละช่วงเลือกแล้วใน combat baseline
- Normal Attack ทำได้ทั้งช่วงรอ SI และช่วงพัก ACD แต่หยุดเมื่อเริ่มร่าย CT (ข้อสรุป Q-001)
- ไม่มี cooldown รายสกิลแยก ใช้ซ้ำเมื่อคิววนกลับมาถึงตามกติกา SP/สถานะและเงื่อนไขอื่นที่ต้องกำหนด (ข้อสรุป Q-002)
- SP ไม่พอเมื่อถึงคิว ให้ข้ามช่องนั้นแล้วเริ่มช่วงรอของช่องถัดไป (Q-004)
- เริ่มร่ายคือนับว่าใช้สกิลและหัก SP แล้ว ผลร่ายสำเร็จหรือไม่ไม่ย้อนคิวและไม่คืน SP (Q-005/Q-006)
- ปล่อยสกิลตามคิวเสมอเมื่อใช้ได้ ไม่มีเงื่อนไขรอ HP ต่ำหรือเก็บท่าขัดไว้รอบอสเริ่มร่าย (Q-007)
- แต่ละตัวรวมบอสมีเวลาของตน ร่าย/ใช้สกิลพร้อมกันได้ ไม่มีการรอให้คนก่อนทำจนจบทั้งทีม
- สถานะอย่าง stun สามารถขัดการร่ายบอสได้ในกรณีที่ออกแบบไว้
- P-01: หน้า 2/หลัง 2 โจมตีปกติเลือกแนวหน้าก่อน Provoke มีผลต่อท่าที่อนุญาต ฮีลเลือก HP% ต่ำสุดแต่ยังใช้ตามคิวแม้ทุกคนเต็ม
- P-02: Story แพ้เมื่อทีมหมดหรือครบ 90 วินาที ตัวหลักตายคนเดียวไม่จบไฟต์ ฟื้น HP/SP ก่อนเริ่มไฟต์ใหม่ ท้าซ้ำฟรี; โหมดรายวันใช้เวลา 60 วินาทีตาม P-07
- สกิลอัปเลเวลโดยใช้ทรัพยากร เพดานสกิลขึ้นกับเลเวลตัวละคร
- Hi-class เพิ่มสกิล 3–4 สกิลต่ออาชีพ และเปิด Awaken: สกิลกลับ Lv.1 แต่ยังดีกว่าระดับ Max ก่อน Awaken อาจเสริมหรือเปลี่ยนความสามารถ และใช้วัตถุดิบอัปเกรดคนละชนิด

## ศัพท์ที่เสนอ

| ชื่อ | Field | ความหมาย |
| --- | --- | --- |
| Skill Interval (SI) | skill_interval | ช่วงรอก่อนเข้าสกิลช่องถัดไป ปรับด้วย ASPD |
| Cast Time (CT) | cast_time | เวลาร่ายก่อนสกิลสำเร็จ สกิลทันทีมีค่า 0 |
| After-cast Delay (ACD) | after_cast_delay | ช่วงพักหลังใช้สกิล ก่อนเริ่มรอบรอถัดไป ใช้ชื่อ ACD แทน ACT เพื่อไม่สับสนกับไฟล์แอนิเมชัน .act |
| Normal Attack Interval | normal_attack_interval | ระยะห่างของ Normal Attack แยกจาก SI แม้จะใช้ ASPD ร่วมกันได้ |
| Cooldown (CD) | — | เกมนี้ไม่มีตัวจับเวลาคูลดาวน์รายสกิลแยกจากรอบคิว ตามข้อสรุปผู้ใช้ |
| Duration | duration | เวลาที่ผลสกิล/บัฟ/พิษยังคงอยู่ แยกจากช่วงร่ายและพัก |

ชื่อระบบเสนอใช้ “Real-time Skill Rotation” หรือ “ต่อสู้อัตโนมัติตามไทม์ไลน์สกิล”

## ลำดับพื้นฐานตามบรีฟ

```text
SI → CT ช่อง 1 → สกิลสำเร็จ → ACD ช่อง 1
   → SI → CT ช่อง 2 → สกิลสำเร็จ → ACD ช่อง 2
   → SI → CT ช่อง 3 → สกิลสำเร็จ → ACD ช่อง 3
   → SI → CT ช่อง 4 → สกิลสำเร็จ → ACD ช่อง 4 → วนช่อง 1
```

Normal Attack มีตัวจับเวลาของตน ทำได้ใน SI และ ACD หยุดเมื่อเริ่ม CT ตัวละครอื่นและบอสเดินไทม์ไลน์ของตนอยู่ตลอด baselineเก็บเวลาตีที่เหลือเมื่อเข้าCTแล้วresumeตอนออก CT และให้ castชนะเมื่อNAพร้อมเวลาเดียวกัน รวมCT0 ไม่ตีความว่าระหว่าง CT ยังโจมตีปกติได้

| ช่วงของตัวละคร | Normal Attack | คิวสกิล |
| --- | --- | --- |
| SI: รอสกิลช่องถัดไป | ทำได้ | นับช่วงรอ |
| CT: กำลังร่าย | หยุด | รอสกิลสำเร็จหรือถูกขัด |
| ACD: พักหลังสกิล | ทำได้ | พักก่อนเริ่ม SI รอบถัดไป |

ตารางนี้ระบุสิ่งที่ช่วงเวลานั้นอนุญาต สถานะ CC/ตายหรือข้อห้ามอื่นยังสามารถหยุดการกระทำได้ ระยะ Normal Attack ไม่ได้เพิ่มความยาว SI/ACD โดยอัตโนมัติ; baselineกำหนด cast startชนะและเลื่อนNAที่พร้อมพอดีอย่างน้อย1msหลัง CTจบ

baselineใช้ `SI = max(1ms, ceil(1500ms × 100 / max(1, ASPD)))` ASPD150จึงได้1,000ms; NAIฐาน1,500msเป็น clockแยก CT/ACDใช้ CastSpeed ไม่เพิ่มเพดานการรวมบัฟ

แยก ASPD กับ Cast Speed เพื่อให้สายตีเร็วและสายร่ายเร็วมีการลงทุนต่างกัน ต้องดูผลรวมเมื่อ ASPD เพิ่มทั้งจำนวน Normal Attack และรอบสกิล เพื่อไม่ให้เป็นค่าสเตตัสที่คุ้มที่สุดเสมอ CT/ACDที่ฐานเป็น0คง0 ส่วนที่มีเวลาใช้ CastSpeed snapshotตอนเริ่มช่วง ตาม baseline

## การนับคิวและ SP ที่ยืนยันแล้ว

หลักเดียวคือ **เริ่มร่าย = ใช้ช่องสกิลนั้นแล้วและหัก SP** ไม่รอให้ร่ายสำเร็จจึงนับคิว สตั้นเป็นสถานะที่มีผลกับการกระทำ ไม่ใช่คำสั่งเลื่อน/ย้อนคิวอีกชุดหนึ่ง

| เหตุการณ์ | ผลต่อช่องสกิลและ SP |
| --- | --- |
| ถึงคิวแต่ SP ไม่พอ | ข้ามช่องนั้นโดยยังไม่ได้เริ่มร่าย แล้วเริ่ม SI ของช่องถัดไป ไม่หัก SP ของสกิลที่ไม่ได้เริ่ม |
| เริ่มร่ายได้ | นับว่าใช้ช่องนั้นและหัก SP ทันที แม้ผลจะออกในภายหลัง |
| ถูกสตั้นก่อนเริ่มร่าย | ยังไม่ใช้ช่องนั้น หายสตั้นแล้วทำช่องเดิมตามสถานะเวลา ไม่ข้ามเพราะโดนสตั้น |
| ถูกขัดหลังเริ่มร่าย | ช่องนั้นถูกใช้ไปแล้ว ไม่คืน SP และไม่กลับไปร่ายช่องเดิมเพียงเพราะไม่สำเร็จ |
| ถึงคิวฮีลขณะ HP เต็ม หรือท่าขัดขณะที่เป้าไม่ได้ร่าย | ปล่อยตามคิวเมื่อใช้ได้ ไม่มีระบบเก็บท่าหรือข้ามเพราะประเมินว่าจังหวะนี้ไม่คุ้ม |

การนับว่าใช้ช่องแล้วไม่อนุญาตให้เริ่มช่องถัดไปซ้อน CT/ACD/สถานะห้ามกระทำของตัวเอง ตัวอื่นยังเดินไทม์ไลน์พร้อมกันได้ตามเดิม

Q-019 ยืนยันว่า timer คิวยังเดินระหว่าง Stun แล้วค้างที่ Action หายแล้วร่ายทันทีเมื่อใช้ได้: SI/ACD ถึงเวลาได้แม้ห้ามกระทำ ไม่เริ่ม SI ใหม่ทั้งก้อนหลังหาย และไม่สะสม action หลายช่องไว้ยิงชดเชย หากถูกสตั้นซ้ำขณะยังไม่เริ่มช่องถัดไป ต้องไม่กินช่องนั้นเพิ่ม การยกเลิกผลร่ายต้องไม่ทำให้เหตุการณ์สำเร็จเก่าหลุดมาทำงานในภายหลัง ส่วนระยะ ACDหลังถูกขัดและ normal-attack clockระบุแล้วใน combat baseline

ตัวอย่าง SI ครบที่ 1.5s แต่ถูก Stun 1–3s: ready ที่ 1.5s และเริ่ม cast ที่ 3s เมื่อ SP/เงื่อนไขใช้ได้ ไม่ใช่ 4.5s ใช้ readiness + action restrictions แยกกันตาม [extension contracts](14-extension-contracts.md)

## หัวข้อที่ TASK-002 ปิดเป็น baseline แล้ว

- สูตร SI/CT/ACD และช่วงพักหลังถูกขัดอยู่ใน baseline; timerระหว่างStunใช้ Q-019 ไม่มี pauseทั้งคิว
- ช่องว่างสแกนข้ามแบบมีขอบเขต เป้าหายใช้ selectorที่ resolveซ้ำได้ ไม่มี AIถือสกิล
- บัฟรวมไม่มี cap/คนเดิมเพิ่มชั้นตาม D-037/038; lifecycleรายสถานะเป็น TASK-047
- Speed snapshotตอนเริ่มแต่ละช่วง บัฟกลางช่วงมีผลกับช่วงถัดไป
- Normal Attackไม่ขัดร่ายเอง ต้องมี explicit interrupt/CC effect ที่ลงสำเร็จและ castนั้น interruptible
- ยึดการปล่อยตามคิวที่ยืนยันแล้ว ไม่เพิ่ม manual hold/AI เก็บสกิลโดยผู้ใช้ไม่ได้ขอ

ไม่เปิดคำถามเรื่อง SP ไม่พอ/การนับคิว/เวลาหัก SP/เงื่อนไขใช้รายช่องที่ยืนยันแล้วใหม่ เว้นแต่ผู้ใช้เปลี่ยนความต้องการ

## CC และบอสตามคำตอบล่าสุด

- แยกการ “ขัดร่าย” ออกจากการ “หยุดตัว”: บางท่าขัดได้โดยไม่สตันยาว
- แต่ละสกิลบอสระบุว่าขัดได้หรือไม่ได้ และ UI แสดงให้เห็น
- Q-018 ยืนยันให้ CC หยุดตามระยะปกติและ Chain CC ต่อเนื่องได้ ไม่ใส่ global immunity window/diminishing returns เพื่อบังคับตัดคอมโบ
- ผู้ใช้เสนอให้บอสบางตัวมี Passive: เมื่อรับ CC สำเร็จ สะสมบัฟ CC Resistance ชั่วคราวที่เพิ่มขึ้นตาม stack นี่เป็นข้อมูลเฉพาะบอส ไม่ใช่กฎที่ใส่ให้บอสทุกตัว สูตร/เวลา/การหมดอายุยังต้องออกแบบ
- Debuff ลด ATK/DEF และเพิ่มความเสียหายที่รับควรยังมีประโยชน์กับบอส กติกาแปลง hard CC เป็นผลอ่อนลงเป็นข้อเสนอที่ต้องคุย
- ต้องระบุ stack, refresh, cleanse, dispel และ immunity ของแต่ละสถานะ รวมบัฟซ้ำจากตัวหลักกับ NPC อาชีพเดียวกัน

## สกิลที่ต้องลงรายละเอียด และ Awaken สำหรับ milestone ถัดไป

รุ่นแรกจบ Class 2; Hi-class/Awaken/Artifact อยู่ milestone ถัดไปตาม D-020 ไม่เพิ่ม task coding ของระบบอนาคตเหล่านี้เข้า scope รุ่นแรก

- Active 4 ช่องและ Passive ที่เรียนมีผลอัตโนมัติยืนยันแล้ว รายละเอียดที่เหลือคือจำนวน Passive การปลดล็อก ค่าอัปเกรด และการซ้อนผล
- ตาราง skill unlock และ level cap ตามเลเวลตัวละคร ไม่ให้ตัวละคร Lv.1 อัปทุกสกิล Max
- Awaken ทำได้ทันทีเมื่อ Hi-class หรือสกิลเดิมต้อง Max? บังคับหรือเลือกทำ?
- นิยาม “Awaken Lv.1 ดีกว่าเดิม Max” ต้องตรวจผลหลักที่เทียบได้ เช่น ดาเมจ/ฮีล/บัฟ พร้อมประโยชน์ใหม่ และไม่ทำให้บิลด์เดิมใช้ไม่ได้เพราะ SP/เวลาร่ายเพิ่ม
- แยกเลเวลตัวละคร เลเวลสกิล และระดับ Awaken ออกจากกัน; slot สกิลควรตามสกิลเดิมต่อได้หลัง Awaken
- Artifact เปลี่ยนคุณสมบัติบางสกิล ต้องระบุความสัมพันธ์กับ Awaken และเพดานการซ้อนผล

## แนวทางพิสูจน์หลังสเปกพร้อม

ตัวจำลองต่อสู้ควรใช้เวลาเกมเดียวกัน แยกจากการวาดภาพ เพื่อให้ผลไม่เปลี่ยนตาม FPS และจำลองหลายบิลด์ได้ ใช้ phase order และ locked cast completion batch ใน combat baseline สำหรับดาเมจ/interrupt/ตายเวลาเดียวกัน

กรณีที่ต้องสาธิต: สองฝ่ายร่ายทับเวลากัน, ASPD สูงทำให้ SI ลดตามสูตร, สกิล CT=0, CC ขัดท่าที่อนุญาต, ท่าบอสขัดไม่ได้, SP ไม่พอข้ามไปเริ่ม SI ช่องถัดไป, สตั้นก่อนร่ายไม่กินช่อง, เริ่มร่ายแล้วเสีย SP แม้ถูกขัด, สตั้นซ้ำไม่กินช่องถัดไปที่ยังไม่เริ่ม, ฮีลเต็ม HP ยังใช้ตามคิว และตัวตายกลางร่าย มี expected traces ที่คำนวณแล้วใน combat-cases.json ผลรันกับ coreจริงยังเป็นงาน M1

ข้อมูลเกม/ตัวเลข/เงื่อนไขสกิลแยกจาก metadata ภาพ ACT/STR และ visual recipes ที่เตรียมไว้ สกิลที่มีชื่อเดียวกันไม่จำเป็นต้องใช้ตัวเลขหรือกติกาของ RO เดิม
