# หน้าจอเกมแบบมือถือ (Game shell)

20 ตุลาคม 2026 · TASK-048 · ตามคำขอผู้ใช้ D-051 · แทนส่วน layout/desktop ของ [design10](10-ui-and-player-flows.md) เฉพาะหน้า `/play`; กติกาเกม คำสั่ง เซฟ และ receipt เหมือนเดิมทุกอย่าง

## สิ่งที่ผู้ใช้ขอ (ยืนยันแล้ว)

- แถบทรัพยากรต้องเล็ก ไม่กินพื้นที่
- หน้าหลักเป็นฉากทีมเดินตีมอนตัวอ่อนไปเรื่อยๆ และมอนแต่ละด่านไม่ค่อยซ้ำกัน
- ปุ่มท้าบอสเป็นรูปดาบไขว้ อยู่ขวาล่าง เหนือ bottom bar เล็กน้อย
- เมนูล่าง: Backpack / Team / Buddy / Store (ล็อก) / Crafting (ล็อก)
- หน้าตัวละคร: ช่องอุปกรณ์ 3 ซ้าย, ตัวละครตรงกลาง, 3 ขวา, ใต้ตัวละครมีปุ่ม Stats / Skill / Upgrade และแถบเลือกตัวละครด้านล่าง
- แตะช่องอุปกรณ์แล้วมี Upgrade (บอกว่าใช้ทรัพยากรอะไรเท่าไหร่) กับ Change (popup รายการที่เปลี่ยนได้ เรียงตาม Level และ Rarity)
- หน้า Skill: รายการสกิลซ้าย, รายละเอียดขวา (Lv ปัจจุบันได้อะไร / เลเวลถัดไปได้อะไร / ปุ่ม Upgrade), ช่องสกิล 4 ช่องด้านล่าง, ปุ่ม Back
- หน้า Stats: Base Stats, Additional Stats (ต้านสถานะ/สตั้น, หลบ, Ignore DEF ฯลฯ), กราฟหกเหลี่ยมซ้าย และแถว STR/AGI/VIT/INT/DEX/LUK พร้อมปุ่ม + ขวา, ปุ่ม Back
- กระเป๋าเป็นตารางช่อง และของที่สวมมีป้าย [E]
- UI โดยรวมต้องดูทันสมัย

## โครงหน้าจอ

```text
┌[อวตาร Lv][ชื่อ อาชีพ][ทอง][EXP][Crystal]      (●)(เสียง)(ตั้งค่า)┐  HUD สูง 66px
│                                        [แผนที่ ฟาร์ม 1-3]  │
│                                        [เป้าหมาย บอส 1-5]  │
│        ทีม 4 คนเดิน/ตีมอน (canvas เต็มกรอบ)                 │
│                                                              │
│ [หีบ AFK 0:56]                                 (⚔ ท้าบอส)   │
├ [กระเป๋า] [ทีม] [ตัวละคร] [ร้านค้า🔒] [คราฟต์🔒] ┤  bottom bar 70px
```

หน้า Backpack / Team / Buddy / Skill / Stats เป็น layer ทับฉาก (ฉากหยุดวาดระหว่างนั้น) HUD และ bottom bar ยังอยู่ ระหว่างสู้บอสเปิดดูหน้าได้ แต่คำสั่งปรับตัวละครถูกปิดตามกติกา `BUILD_LOCKED_DURING_BATTLE` เดิม

D-076 / TASK-056 (21 ต.ค. 2026): หน้าแรกเอารูปทีมวงกลมสี่ตัวออก เปิดทีม/ตัวละครผ่านเมนูล่าง; Stats/Skill มีปุ่ม ‹ › มุมขวาบน วนตัวในทีมก่อนแล้วตัวที่พักเหมือน roster strip อยู่หน้าเดิมและไม่บันทึกเกมเพราะเปลี่ยนตัว Draft Status/เลือกช่องสกิลของตัวเก่าไม่ติดไปตัวใหม่ คิวสกิลอยู่ด้านล่างตาม D-077 รายการและรายละเอียดเลื่อนแยกกัน Timeline เปิดใน sheet ส่วนผลสกิลระดับถัดไปกดขยายดูได้ UI ลด HUD เป็น 58px / เมนูล่าง 60px ลดแผงอุปกรณ์/รูปเพื่อน/ช่องว่าง กระเป๋า 6 คอลัมน์โดยจัด CSS จริง ไม่ใช้ zoom หรือย่อ viewport; ชื่อ/ตัวเลข/ข้อมูลฉบับเต็มยังเปิดดูได้

ไฟต์บอสใช้ canvas เดียวกัน: แถบ HP บอสพร้อมเวลา, ปุ่มสถิติ/Timeline/ถอยทัพ, การ์ดทีม 4 ใบด้านล่าง แล้วจบด้วยการ์ดผลลัพธ์ (รับรางวัล / ท้าด่านถัดไป / ปรับทีม / ลองใหม่ / กลับไปฟาร์ม)

Timeline (D-060): สกิลที่ขัดร่ายศัตรูสำเร็จมีป้าย ⚡ (ถ้าขัดหลายครั้งจะแสดงจำนวน) และรายละเอียดบอกชื่อสกิลที่ถูกขัด ส่วนสกิลที่ถูกขัดมี ✕ ไอคอนจาง และแถบร่ายลายทางแดง ข้อมูลมาจาก `cast_interrupt.action_id` ของ engine ไม่มีการเดาจากลำดับ event

หน้าตัวละคร: การ์ดเพื่อนทั้ง 7 ใบอยู่ในกริด 4 คอลัมน์ (4+3) พอดีความกว้างจอ ไม่มีแถบเลื่อนข้างที่การ์ดถูกตัดขอบ

## ไอคอนและ asset

`src/renderer/shell-visuals.json` เป็นข้อมูล presentation ที่ `scripts/build_runtime_assets.py` อ่านเข้า runtime pack (`index.shell`) เหมือน `combat-visuals.json` ไม่อยู่ใน engine/content hash:

- เมนูและปุ่ม: `ro_menu_icon` (item/party/status/bank/battle/navigation/skill/info) แบบปกติ `_1`, เรืองแสง `_2`, และสีเทา `_3` สำหรับเมนูที่ล็อก
- ทรัพยากร: ไอคอนไอเท็ม 24px (Gold Coin, Blue Gemstone, Emperium, Old Magic Book, Oridecon, Star Dust, Wet Card Album), หีบ AFK = Old Blue Box, Crafting = Anvil; EXP ไม่มีไอคอนไอเท็มที่ตรงความหมาย จึงใช้ป้าย CSS
- มอนฟาร์ม 48 ตัวใน 8 บท (ทุ่งปรอนเทรา, ป่าเพยอน, ทะเลทรายมอร็อค, ใต้ดินเกฟเฟน, ถ้ำไบอาลาน …) ทั้งหมดมีสถานะ `exported` และไม่มี missing dependency
- ตรวจด้วยตาเฉพาะ contact sheet ของ `ro_menu_icon` และภาพจาก browser ของ TASK-048 ไม่ได้ตรวจทุกเฟรมของ animation มอนทุกตัว

Pack หลังเปลี่ยน: 319 assets / 638 files / 23.07MB + manifest 0.31MB (งบ 25MiB) content_hash `65b82feb…` เท่าเดิม

## เว็บเล่นส่วนตัว

`play_local.py --refresh-compatible-snapshot` สร้าง snapshot ใหม่ทั้งที่มีเซฟอยู่ได้ เมื่อ content_hash ไฟล์ migration โค้ด `api/` `src/server/` และ gateway ตรงกับ snapshot เดิมทุก byte โดยสำรองฐานข้อมูลด้วย `pg_dump` และเก็บ snapshot เก่าไว้ก่อน ถ้าไม่ตรงจะปฏิเสธด้วย `LOCAL_PLAY_REFRESH_INCOMPATIBLE_*` การย้ายเซฟข้าม content ยังเป็นงาน TASK-040
