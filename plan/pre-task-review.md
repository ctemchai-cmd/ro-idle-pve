# ประเด็นปิดแผนก่อนแตก task

สถานะการทำงานล่าสุดดู [overview](overview.md) และตำแหน่งไฟล์ task ผลตรวจ/ข้อเสนอด้านล่างเก็บเป็นประวัติการออกแบบ M0 ไม่ใช่สถานะ runtime ปัจจุบัน


อัปเดต: 19 ตุลาคม 2026 · สถานะ: **Q-001–Q-022 ตอบแล้ว; บัฟบวกไม่มีเพดาน คนเดิมร่ายซ้ำเพิ่มชั้นแยกอายุ**

รอบตรวจการต่อยอด: Q-019–Q-021 ตอบแล้ว — Stun คิวยังรันถึง Action, ท่าเดิมหนึ่งช่อง, ฟาร์ม resources แล้วเลือกกดอัปตัวละคร ดู [extension contracts](design/14-extension-contracts.md) และ [ตัวอย่างประกอบ](examples/composition-contract.json) ที่ปรับแบบจริง Q-017/Q-022 ยืนยันบัฟบวกเพิ่มไม่มีเพดานและคนเดิมร่ายซ้ำเพิ่มชั้นที่หมดอายุแยก แลกด้วย duration/คิว/ดาเมจของตัวบัฟ

ผู้ใช้ขอให้ตรวจช่องว่างทั้ง game design และ level design ก่อนสร้าง task เอกสารนี้รวมการตัดสินใจที่มีผลต่อขอบเขตและ dependency ไม่เปิดคำถามซ้ำเรื่องคิว/สตั้น/Status ที่ยืนยันแล้ว ข้อที่ไม่ได้ตอบยังคงเป็นข้อเสนอ ไม่ถือว่าการเงียบเป็นการยืนยัน

## งานออกแบบที่ผู้ช่วยจัดทำได้หลังหลักการชัด

ไม่จำเป็นต้องถามผู้ใช้ทีละค่าดาเมจ แต่ต้องมีข้อมูลให้ตรวจรับก่อนเขียนระบบที่ใช้มัน:

- ตาราง STR/AGI/VIT/INT/DEX/LUK → ค่าต่อสู้, ราคาแต้ม, เพดาน, SI/CT/ACD, และการฟื้น SP โดยไม่เพิ่มความเร็วจากเลเวล/อาชีพอัตโนมัติ
- Spec สกิล: ผล/เป้าหมาย/การโต/CT/ACD/SP/ธาตุ/สถานะ/proc/asset recipe ทุกสกิลในรุ่นที่เลือก; Passive แยกจาก Active; การอัปเลเวลไม่เปลี่ยนเวลาโดยเงียบ ๆ
- ผลของบัฟ/พิษ/ฮีลซ้ำ การต้าน CC ของบอส และเวลาที่เปลี่ยนจากบัฟ โดยยึด cast start counts as used ที่ยืนยันแล้ว
- ตารางค่าอัปเกรด รายได้ฟาร์ม ดรอป ของซ้ำ กาชา และเป้าหมายเวลาสะสมต่อ upgrade; ตรวจต้นทุน Supreme จาก Common 729 ชิ้นควบคู่ drop ระดับสูง
- ตารางด่าน/บอสที่มีโจทย์แตกต่างกันและวิธีแก้หลายทาง ดู [level design](design/06-level-design.md)
- UI: ทีม/สกิล/Status/อุปกรณ์/การ์ด/แผนที่/โหมด/ผลต่อสู้; preview เวลาที่เปลี่ยน และอธิบายสาเหตุแพ้
- Supabase Auth/เซฟหลัก, autosave/กู้ checkpoint, revision/ป้องกันรับรางวัลซ้ำ, รุ่นข้อมูลและสำรองก่อน migration, export/import/reset ที่รองรับ cloud
- Vercel Development/Preview/Production และ runtime asset pack ที่คัดเฉพาะสิ่งใช้จริง ไม่ deploy คลังทั้งหมด
- กติกาเวลาเกมและตัวจำลองแยกการวาด เพื่อให้การพักแท็บและ FPS ไม่เปลี่ยนผล และตรวจเรื่องการรับรางวัลซ้ำได้
- scenario/seed/content version และรายงาน JSON/CSV สำหรับ batch/A-B; pure progression calculations เป็นช่องทางต่อยอดจำลองการฟาร์ม/อัปตัวในอนาคต

รายละเอียดเทคนิคและตารางตัวเลขเป็นงานออกแบบข้อมูล/ตรวจความสอดคล้องได้ก่อน implementation ไม่เปลี่ยนข้อเสนอเป็นข้อยืนยันเพื่อข้ามคำถามค้าง

แตกเป็น tasks_001.md–tasks_047.md แล้ว แต่ละไฟล์มีผลส่งมอบ dependency ขั้นตอน เกณฑ์ตรวจรับและตารางหลักฐาน เริ่ม M0 และ TASK-001/002/047 ผ่าน self-review แบบแล้ว ส่วนตัวเกมยังไม่เริ่มพัฒนา ดูสถานะจริงและรายการครบใน [overview](overview.md)

ตรวจความชัดเจนเชิงเนื้อหาและความครอบคลุมรอบเพิ่มเติมแล้วใน [ผลตรวจ task](task-audit.md) M0 ต้องส่งตัวเลข/ข้อมูล/เคสที่อ้างอิงได้จริงก่อน TASK-014 ผ่าน ส่วน Hi-class/Class 3/Pet/Rune และ simulation autoplay เต็มรูปแบบยังเป็น roadmap ที่ต้องออกแบบก่อนแตกงานแพตช์นั้น

[ผลตรวจสถาปัตยกรรม](architecture-audit.md) พบ A-01–A-08 ที่ยังไม่ปิด: module/state ownership, คำสั่งเซฟ/receipt, จุดรันสูตรชุดเดียว, compatibility, การหยุด/กลับเข้าไฟต์, คืนทุน และสัญญาต่อยอด ต้องปิด design ใน M0 แล้วมีผลรันพิสูจน์แกนและเซฟตามงานรับผิดชอบ จึงยังไม่ถือว่าโครงสร้างแน่นครบเพียงเพราะ task/dependency ผ่าน

M0 ตรวจสเปก ตารางตั้งต้น และผลคาดหวังด้วยการอ่าน/คำนวณก่อน ไม่บังคับผลจากตัวจำลองที่ M1 จะสร้าง TASK-014 รอ M0 ครบแล้วเปิดทางให้ coding ตามที่ผู้ใช้ต้องการออกแบบก่อน ส่วนงานหลัง gate อ้าง dependency เฉพาะผลส่งมอบที่ใช้จริง; Preview ทำได้เมื่อวงจรหลักพร้อม ไม่ต้องรอ M4 ทั้งก้อน
